This project is also packaged as a desktop application using **Electron**. It bundles the web interface (HTML/CSS/JavaScript) into native macOS, Windows, and Linux applications.

# Пульт оператора ЦУП · «ИнтроСат»

Прототип рабочего места оператора центра управления полётами учебного спутника
«ИнтроСат». Принимает телеметрию, показывает состояние модулей, ведёт журнал
и позволяет просматривать записи сеансов.

---

## 1. Быстрый старт

```text
1. Запустить эмулятор телеметрии (раздел 2).
2. Открыть index.html в браузере.
3. В шапке должно появиться «Приём телеметрии».
```

Если вместо этого горит аварийная полоса «Эмулятор недоступен», значит сервер
не запущен или указан неверный адрес — проверьте его на экране «06 Настройки»
(поле «Адрес эмулятора», кнопка «Проверить соединение»).

### Особенности запуска

| Ситуация | Что делать |
| --- | --- |
| Chrome, Edge, Firefox, любой компьютер | открыть `index.html` двойным щелчком — работает |
| Safari, планшет, телефон | положить папку на компьютер с эмулятором и подключиться к его адресу (раздел 3) |

Safari запрещает запросы к `http://` со страниц, открытых по `file://`, поэтому
для него и для мобильных устройств нужен вариант из раздела 3.

---

## 2. Источник данных: эмулятор телеметрии

Эмулятор — обязательная часть задания
([mcc-hack/data-emulator](https://github.com/mcc-hack/data-emulator)). Он нужен
и в файловом режиме (демонстрация без конструктора), и при подключении реального
спутника.

```bash
# 1. Получить эмулятор
git clone https://github.com/mcc-hack/data-emulator

# 2. Запустить (Python 3.10+; в файловом режиме зависимостей нет)
cd data-emulator
python emulator.py
#   → выберите номер файла с данными
#   → дождитесь: «Адрес: http://127.0.0.1:8765/telemetry»
```

Полезные ключи:

```bash
python emulator.py --list-files                        # список файлов телеметрии
python emulator.py --file 01_normal_flight.csv         # сразу без меню
python emulator.py --file 01_normal_flight.csv --interval 0.05   # чаще кадры
python emulator.py --file 02_sensor_faults.csv        # отказы датчиков
python emulator.py --file 03_radio_noise.csv           # повреждения в эфире
```

Реальный конструктор читается так же, меняется только источник:

```bash
python -m pip install -r requirements.txt
python emulator.py --source serial --port COM3 --baudrate 115200
```

Код пульта при этом не меняется: он обращается к тому же адресу.

### Важная особенность эмулятора

`GET /telemetry` возвращает **только последний** кадр, а не поток. Поэтому между
двумя полученными пакетами счётчик «Время МК» может вырасти на несколько, и часть
кадров физически не доходит до пульта. Это не дефект приёмника: пульт считает
пропуски по счётчику МК и показывает их отдельной строкой «Пропущено по счётчику
МК» вместе с «Полнотой потока». Если полнота падает ниже 90 %, пульт сам
уменьшает интервал опроса (минимальный — 40 мс) и пишет об этом событие в журнал.

При очень быстром эмуляторе (`--interval 0.05` и меньше) поток теряется
неизбежно: счётчик и время прихода кадров в этом случае просто не совпадают.

## 4. Что умеет пульт

Пульт построен как приборная стойка. Слева — постоянная панель канала и ленты
событий: она не переключается вместе с экраном, поэтому состояние связи видно из
любого раздела. Шесть экранов справа (клавиши `1`…`6`).

### Панель приборов

* **Вердикт в шапке** — одно слово на весь пульт: `НОРМА`, `ВНИМАНИЕ`, `АВАРИЯ`
  или `НЕТ ДАННЫХ`, рядом — причина, которой достаточно для первого действия.
  Читается периферийным зрением, не заставляя искать глазами нужную строку.
* **Приборы** — пять модулей комплекта: микроконтроллер STM32, датчик положения
  (гироскоп + акселерометр + магнитометр), четыре датчика освещённости, модуль
  питания, плата маховика. У каждого — показание, уровень состояния и текст
  причины. Положение выбирается настройкой **Отображение → Положение приборов**:
  * `справа столбиком, в «Обзоре»` — по умолчанию. Список модулей встаёт
    правой колонкой обзора, графики становятся шире (на окне 1920 px — 1264 px
    против 926 px). Виден только в «Обзоре».
  * `слева, в постоянной панели` — видно со всех экранов, но графики уже.
* **Канал** — состояние приёма и четыре числа: возраст кадра, полнота потока,
  пропущенные пакеты, ошибки опроса. Частоты здесь нет — она уже стоит в шапке
  и показывала бы то же самое число второй раз.
* **События** — живая лента сеанса, обрезанная по высоте панели: важна свежесть
  верхних записей, а не их количество. Счётчик справа ведёт в полный журнал на
  экране 05 — из обрезанной ленты иначе некуда пойти.

Рельс живёт в обоих режимах: канал и лента нужны на всех экранах, поэтому
уходят они вправо только вместе с приборами — по отдельности это делать нечего.
При нехватке высоты место отдаёт не лента, а таблица приборов: лента не
сжимается ниже трёх записей (на 1440×900 с приборами слева раньше схлопывалась
до 31 px, а восемь записей помещались в 4 px), а таблица модулей прокручивается
собственной полосой.

Переносится один и тот же узел между двумя родителями, а не дублируется
разметка, — иначе таблица модулей оказалась бы в двух экземплярах и обновлялся
бы только один. На узких экранах (≤ 1080 px) приборы, если они справа, идут
первыми: это сводка состояния аппарата, и отодвигать её под дамп пакета нельзя.

### 01 Обзор

* **Напряжение питания** — график с рабочим диапазоном и границами аварии.
* **Параметры во времени** — шесть групп (батарея, маховик, освещённость,
  акселерометр, гироскоп, магнитометр). Окно 2/5/15 минут. Ряды можно
  скрывать щелчком по легенде — на графике одновременно четыре оси читаются
  хуже, чем одна-две.
* **Поток данных** — длительность сеанса, задержка опроса, пропущенные пакеты,
  полнота потока за сеанс и за последние две минуты.
* **Целостность полей** — карта «поле × последние 64 пакета». Повреждённое поле
  видно точечно: по пакету в журнале видно только «пакет плохой», здесь видно,
  какой именно датчик молчит.
* **Текущий пакет** — сырая строка целиком, как её отдал эмулятор.

### 02 Показания датчиков

* **Показания датчиков** — все 16 полей: значение из пакета, физическая величина
  с единицей измерения и признак достоверности.
* **Причины отклонений** — что и сколько раз ломалось за сеанс.
* **Кадр по полям** — производные величины: модули векторов ускорения, угловой
  скорости и магнитного поля, а также углы ориентации.

### 03 Ориентация

* **Положение спутника** — трёхмерная модель: корпус и две солнечные панели по
  бортам. Грани залиты плотным цветом и обведены чернильной линией: объём даёт
  не мягкая тень, а обводка — при плоском освещении именно она делает модель
  читаемой. Панели набраны ячейками, как настоящие.
* **Связанная СК** — три луча X Y Z из начала координат, у каждого свой цвет из
  палитры графиков: так вектор можно сопоставить с рядами на графиках. Оси
  рисуются поверх аппарата — иначе корпус их закрывает.
* На сцене только аппарат и оси. Ни опорной СК, ни отметки солнца, ни вектора
  угловой скорости, ни координатной сетки: всё это перекрывало силуэт, а
  числовые значения есть рядом в таблице ниже, где их можно прочитать точно.
  Солнце при этом не исчезает из вычислений — им затеняются грани, и свет
  закреплён относительно наблюдателя, поэтому при повороте корпуса освещение
  не скачет.
* Перспектива настоящая: ближние точки крупнее дальних примерно в 1,34 раза. При
  плоской проекции дальняя панель читалась бы как ближняя.
* Задние грани отсекаются по знаку третьей координаты кадра. Нельзя по
  скалярному произведению нормали на центр грани: у ящика с центром в начале
  координат эти векторы параллельны, произведение всегда положительно, и
  невидимыми оказываются все грани разом.
* Сцену можно вращать мышью, колесо — масштаб, двойной щелчок — исходный вид.
* **Углы ориентации** — крен, тангаж, курс.
* **Угловые скорости** и **Магнитное поле** — модули и компоненты.

### 04 Команды

Форма команды с проверкой аргумента, очередь передачи с состоянием каждой
команды, журнал команд и состояние канала передачи.

### 05 Журнал

Лента событий с фильтром по уровню и поиском по тексту/времени, журнал пакетов
с поиском и фильтром «только отклонённые», отчёт о сеансе, работа с записью:
открыть лог из файла,
продолжить прошлый сеанс, воспроизведение с темпом ×0,25…×16 и без пауз.

## 5. Протокол пакета

18 полей, разделитель `;`:

```text
ПРЕАМБУЛА;ВРЕМЯ ОТ ЗАПУСКА МК;АКБ;СД1;СД2;СД3;СД4;AX;AY;AZ;GX;GY;GZ;MX;MY;MZ;МАХОВИК;ПОСТАМБУЛА
AA55         ;1204               ;8420;…                    ;…                             ;0D0A
```

| Поле | Единицы | Преобразование | Допуск |
| --- | --- | --- | --- |
| `ВРЕМЯ ОТ ЗАПУСКА МК` | с | как есть | неотрицательное целое |
| `АКБ` | В | ÷ 1000 | 0…65535 мВ, правдоподобно 2…20 В |
| `СД1`…`СД4` | усл. ед. | как есть | 0…65536, насыщение от 65530 |
| `AX`, `AY`, `AZ` | g | ÷ 16384 | ±32768, насыщение от 32700 |
| `GX`, `GY`, `GZ` | °/с | ÷ 131,072 | ±32768, насыщение от 32700 |
| `MX`, `MY`, `MZ` | Гс | ÷ 1711,6 | ±32768, насыщение от 32700 |
| `МАХОВИК` | усл. ед. | как есть, знак задаёт направление | ±32768 |

Правила разбора (`js/telemetry.js`):

* преамбула и постамбула сверяются с настройками — в файле с помехами они
  повреждаются первыми;
* число полей должно быть ровно 18;
* `OFF` означает физически отключённый датчик: пакет остаётся пригодным,
  модуль уходит в аварию «нет связи» — это не то же самое, что сбой канала;
* любое другое нечисловое значение (`NaN`, `?`, `CRC_ERROR`, пустая строка)
  считается повреждением поля;
* больше трёх повреждённых полей — пакет отбрасывается как хаотичный;
* повреждённое время пакета отбрасывает пакет целиком: без времени его нельзя
  положить на шкалу.

## 6. Нештатные ситуации

### Как увидеть их за сорок секунд

Это важно знать до защиты. Файлы из репозитория устроены так:

| Файл | Первая нештатная ситуация | Через |
| --- | --- | --- |
| `01_normal_flight.csv` | нет ни одной на 100 000 кадров | — |
| `02_sensor_faults.csv` | кадр 10 000, МК 10 000 (`АКБ` → `OFF`) | **16 мин 40 с** |
| `03_radio_noise.csv` | кадр 143, МК 143 (постамбула `0D00`) | 14 с |

Если запустить `02_sensor_faults.csv` и смотреть три минуты, экран будет
полностью зелёным — и это не дефект приложения, а расположение данных.

**Надёжный путь — воспроизведение в самом пульте.** Экран «05 Журнал» →
«Открыть лог из файла» → выбрать `02_sensor_faults.csv` прямо из папки
эмулятора → темп ×16 или «без пауз». Файл разбирается тем же кодом, что и
живой поток, но приходит построчно, поэтому:

* первый отказ появляется через ~40 секунд вместо 16 минут;
* «Полнота потока» показывает 100 %, потому что ничего не теряется;
* файл принимается в исходном виде эмулятора — править его не нужно.

Это заодно демонстрирует требование п. 6 ТЗ: журнал сохранён, сохранённый
журнал открыт и проигран заново.

**Путь через эмулятор** — если нужна именно живая передача. Обрежьте файл
так, чтобы начать за пару сотен кадров до первого отказа:

```bash
python -c "p='data/02_sensor_faults.csv';l=open(p,encoding='utf-8').read().splitlines();open('02_demo.csv','w',encoding='utf-8').write('\n'.join([l[0]]+l[9900:16000])+'\n')"
python emulator.py --file 02_demo.csv
```

Теперь `АКБ` отключается через 10 секунд, `СД1` — через 4 минуты, и так далее.
Порядок отключений в файле: `АКБ` → `СД1` → `СД2` → `СД3` → `СД4` →
акселерометр → гироскоп → магнитометр → маховик, примерно по 244 секунды на
каждый. Дальше идут насыщения измерителей (МК 44 223 и далее) и мусорные
значения вместо чисел (МК 54 000).

Оговорка: чем быстрее эмулятор, тем ниже полнота потока — при `--interval 0.05`
пульт физически не успевает опрашивать чаще, чем меняются кадры. Это свойство
эмулятора, а не приёмника, и честно видно в показателях.

### Как пульт на это реагирует

| Ситуация | Поведение пульта |
| --- | --- |
| Эмулятор не запущен | аварийная полоса с командой запуска, опрос замедляется до 1 с, счётчик ошибок растёт |
| Эмулятор запущен, данных ещё нет (HTTP 204) | состояние «Ожидание данных», аварии нет |
| Передача остановилась | после настраиваемого интервала все модули получают статус «показания устарели» |
| Датчик помечен `OFF` | авария модуля, в карте целостности строка окрашивается, график показывает разрыв |
| Повреждено значение поля | внимание, пакет учитывается как «с замечаниями», точное поле видно в карте |
| Повреждена преамбула или постамбула | пакет отклоняется, причина попадает в список причин |
| Счётчик МК откатился назад | событие в журнале; три отката подряд трактуются как перезапуск МК |
| Счётчик МК перескочил вперёд | засчитывается пропуск, полнота потока падает |
| Эмулятор перезапустился и начал файл заново | тот же откат счётчика — событие, ложного «перезапуска МК» не возникает |

## 7. Передача команд

Эмулятор телеметрии — приёмник: он реализует только `GET /telemetry`, а на любой
другой путь отвечает 404. Изображать передачу команд было бы враньём, поэтому
пульт при первой отправке делает один запрос к адресу команды
(`http://127.0.0.1:8765/command`) и сообщает результат:

* канал недоступен или ответили отказом → команды выполняются **в локальной
  модели** с пометкой «Выполнена локально: эмулятор не принимает команды»;
* на `WHEEL_SET` дополнительно показывается ожидаемый результат — например
  «ожидаемая скорость маховика −12000 (сейчас 26465)», чтобы оператор видел
  последствие, а не только галочку;
* если канал передачи отвечает и доступен, команда уходит настоящим `POST`,
  а её состояние берётся из кода ответа;
* при аварии канала команда не помечается выполненной.

## 8. Настройки

Экран «06 Настройки»: адрес эмулятора, интервал опроса, время потери связи,
преамбула и постамбула, пороги напряжения (по умолчанию 7,2–8,5 В — рабочий
диапазон, 6,6 и 8,7 В — авария), тема оформления, положение приборов, пороги
на графике, мигание аварии. Настройки, журнал и прошлый сеанс хранятся в
браузере (`localStorage`) и выгружаются в JSON одним файлом.

Положение приборов — единственная настройка, которая применяется сразу, без
кнопки «Сохранить»: переменная одна, её тут же видно на экране, а лишний шаг
только путает. Остальные поля копятся и записываются по кнопке, потому что их
много и менять их разом незачем.

### Анализ сеанса

* **Экспорт сессии** — на экране «06 Настройки», кнопка «Экспорт сессии · JSON»
  сохраняет снимок всего сеанса: статистику потока (принято, отброшено,
  полнота, возраст кадра, время в аварии), список модулей с уровнями, события,
  последние пакеты и конфигурацию. Файл можно открыть позже и перепроверить,
  откуда взялся тот или иной вердикт.
* **Сводка за сеанс** — на экране «01 Обзор», правая колонка «Поток данных»:
  длительность сеанса, частота обновления, задержка опроса, пропущенные пакеты,
  полнота потока за сеанс и за последние 2 минуты, время в аварии и число
  модулей с замечаниями. Время в аварии накапливается, пока уровень тревоги
  равен `АВАРИЯ` — это помогает оценить, сколько времени apparatus провел
  в нештатном режиме.

Горячие клавиши: `1`…`6` — экраны, `P` — заморозить приём, `G` — следующая группа
графика, `L` — показать или скрыть все ряды, `?` — справка.

## 9. Устройство проекта

```text
cup-hack/
├── index.html        разметка всех экранов, без служебной логики
├── css/app.css       дизайн-система и вёрстка, один файл
├── js/
│   ├── telemetry.js  протокол: разбор пакета, допуски, единицы измерения
│   ├── analysis.js   состояние модулей, статистика потока, отчёт о сеансе
│   ├── views.js      отрисовка на canvas: графики, карта полей, 3D-сцена
│   └── app.js        состояние, опрос эмулятора, команды, журнал, настройки
├── tests/            проверки (раздел 10)
└── tools/            сборка одного файла (раздел 15)
```

Модули связаны одним временем: `telemetry` ничего не знает о модулях и DOM,
`analysis` — о браузере, `views` — о состоянии. `app.js` читает их результаты и
обновляет интерфейс. Благодаря этому разбор пакета проверяется без браузера, а
отрисовка — без эмулятора.

Композиция экрана — трёхколоночная: постоянная панель приборов, рабочая область
и смысловой столбец таблиц. Панель не переключается вместе с экраном, поэтому
состояние аппарата остаётся видимым на всех шести разделах. Разделы внутри
столбца отбиты волосяными линейками и воздухом, а не рамками: рамка в проекте
осталась только там, где элемент действительно что-то содержит — поле ввода,
кнопка, модальное окно и блочный код.

Поток данных:

```text
эмулятор ──GET /telemetry──▶ poll() ──▶ ingest() ──▶ Stream ──▶ отрисовка
                                  │
                                  └── кадр последний, пропуски считаются
                                      по счётчику МК
```

Ключевые решения:

* **Отрисовка по требованию.** Тяжёлые полотна перерисовываются только при новых
  данных, а не в цикле 4 Гц: счётчики обновляются всегда, графики — когда есть
  что рисовать.
* **История ограничена, счётчики — нет.** Пульт хранит последние 20 000 пакетов
  и 5 000 записей журнала: измеренная цена одного кадра — 1111 байт, то есть
  38 МБ в час при 10 Гц, а длинный сеанс без ограничения съедал бы сотни
  мегабайт. 20 000 кадров — это 33 минуты при 10 Гц, с запасом перекрывающие
  самое длинное окно графика. Итоги сеанса при этом полные: счётчики
  накопительные, окно графика ищется делением пополам, а не перебором.
* **Никакого сглаживания.** Пропуск данных на графике остаётся разрывом линии:
  интерполяция создала бы значения, которых не было.
* **Цвет дублируется формой.** Уровень состояния кодируется не только цветом, но
  и формой глифа (круг, треугольник, квадрат) и подписью — иначе индикатор
  нечитаем при нарушениях цветовосприятия.
* **Устаревшие данные не выдаются за свежие.** При потере связи показания
  остаются на экране, но получают пометку «показания устарели».

## 10. Проверки

Проверки лежат в `tests/` и не требуют ничего, кроме Python 3.10+ и браузера.

```bash
python3 tests/run_all.py            # синтаксис, статика, регламент, сборка
python3 tests/static_check.py       # только статическая часть
python3 tests/compliance_check.py   # только соответствие регламенту и ТЗ
python3 tests/serve.py 8779         # сервер проверок без кэширования
```

Открыв `http://127.0.0.1:8779/`, можно прогнать фаззинг в консоли браузера:

```text
runFuzz(1000, 42)                   // разбор пакета: N итераций, фиксированное зерно
runUiFuzz(300, 7)                   // живой интерфейс: случайные действия оператора
```

### Что делает каждая проверка

| Файл | Что проверяет |
| --- | --- |
| `tests/static_check.py` | ссылки `#id` из JS на реальные элементы, дубли идентификаторов, цели `label`/`aria-controls`, классы без правил, CSS-переменные, мёртвый код, баланс тегов, сырые данные в `innerHTML` |
| `tests/fuzz.html` | `parse()` на 120 000 пакетах: обрезка, лишние поля, `OFF`, мусорные токены, `1e3`, `0x10`, типографский минус, числа за пределами `Number`. Инварианты: разбор не бросает исключений, всегда 16 полей, уровень 0…2, `mk` — число, разбор детерминирован, счётчики ограничены, отчёт без `NaN` и `undefined` |
| `tests/ui_fuzz.html` | реальный интерфейс во `<iframe>`: случайные переключения экранов, темы, заморозка, настройки, команды, воспроизведение записей, семь размеров окна от 280 px до 2400 px и загрузка 6000 пакетов подряд. Проверяет мусор в тексте, целые полотна, неотрицательные счётчики, согласованность тревоги, экранирование и то, что **каждый сетевой адрес ведёт на хост источника** |
| `tests/mock_emulator.py` | эмулятор для интеграционной проверки: `GET /telemetry`, 404 на прочие пути, `--commands` переключает ответ `/command` на 405 |
| `tests/layout_probe.html` | раскладка на заданной ширине окна. Медиазапросы внутри кадра считаются от его ширины, поэтому проверка не зависит от размера экрана, на котором открыт пульт |
| `tests/serve.py` | сервер без кэширования: обычный `http.server` отдаёт старую копию `js/app.js`, и фаззинг продолжает находить уже исправленные ошибки |
| `tests/compliance_check.py` | 30 требований регламента и ТЗ, которые проверяются механически: комплект «ИнтроСат», интерфейс передачи, сохранение лога, требования к интерфейсу, критерии оценивания, отсутствие привязки к машине разработчика |

### Что нашли эти проверки

* `Number(x) || default` в сохранении настроек превращал ноль в единицу: выбор
  «скрыть пороги» и «выключить мигание» не сохранялся вовсе;
* адрес канала команд собирался склейкой строк, и при адресе источника без пути
  (`http://127.0.0.1:8765`) терялись хост и порт — запрос уходил на `http://command`;
* первое же сохранение настроек выключало автоподборку интервала опроса, даже если
  оператор его не трогал.

Остальное оказалось в порядке: 1 500 000 итераций разбора и 1 000 000 итераций
интерфейса проходят без единого замечания.

### Сверка со второй реализацией

В том же протоколе существует независимая однофайловая реализация пульта
(`introsat_cup_клод.html`, 29 КБ против 209 КБ здесь). Она проверена против
живого эмулятора и служит не источником правок, а **эталоном для сверки
семантики пакета**: обе версии получали одни и те же пакеты через воспроизведение
записи, после чего сравнивались уровни модулей и счётчики.

Расхождения — все три в нашу пользу, поэтому из неё ничего не переносилось:

| Сценарий | Этот пульт | Вторая реализация |
| --- | --- | --- |
| Неподвижный спутник, гироскоп `0;0;0` | **норма** | «Нулевые показания: гироскоп» — внимание |
| Насыщение `AX=32765` | внимание, насыщение измерителя | норма |
| ОСД1 = 65531 | внимание, насыщение измерителя | норма |
| Счётчик МК ушёл вперёд на 1000 с | пакет принят, потери учтены | **пакет отклонён** |
| Счётчик МК ушёл назад на 5 с | пакет принят | **пакет отклонён** |

* Нулевая угловая скорость — это норма для невращающегося аппарата, а не отказ.
  Здесь проверка нуля включена для акселерометра и магнитометра и выключена для
  гироскопа осознанно.
* Порог насыщения (32700 и 65530) ловит приближение к пределу измерителя, а не
  уже состоявшееся ограничение: предупреждать надо до обрезки, иначе оператор
  узнаёт о ней по факту.
* Разрыв или откат счётчика МК не отбрасывают пакет: он уходит в счётчик
  потерь и в отчёт о полноте потока. Отклонять данные по одному сбою счётчика
  — значит терять показания, которые ещё можно интерпретировать.

Приём совпал полностью на обычном пакете, на нулевом акселерометре, на
`АКБ = 0` и на отключённом датчике. Иные расхождения объясняются тем, что у
второй реализации нет порогов, карты целостности полей, отчёта о сеансе,
экспорта настроек и горячих клавиш. Идеи её вёрстки — `color-scheme`,
`:focus-visible`, `tabular-nums`, `prefers-reduced-motion`, горизонтальная
прокрутка вкладок — в этом проекте уже присутствуют; не взят только `light-dark()`,
потому что он требует Safari 17.5+ и сломал бы заявленную поддержку 15.4+.

## 11. Что проверено вручную

Пульт запускался против эмулятора с файлами `01_normal_flight.csv`,
`02_sensor_faults.csv` и `03_radio_noise.csv` из репозитория задания:

* приём на частоте 9,6 Гц при интервале кадров 0,1 с, задержка запроса 6–16 мс,
  полнота потока 95…99 %;
* отказы датчиков (`OFF`) — авария нужного модуля, а не всего аппарата;
* повреждения в эфире — раздельная обработка преамбулы, постамбулы, значений и
  времени пакета;
* недоступный эмулятор, HTTP 204, остановка передачи, заморозка приёма,
  воспроизведение записи, отправка команд с неверным и верным аргументом;
* раскладка 1440 px (две колонки), 1000 px и 390 px (одна колонка, таблица
  модулей перестраивается в список), светлая и тёмная темы;
* нагрузка на память: 60 000 принятых пакетов подряд оставляют в истории
  ровно 20 000 кадров и 5 000 записей журнала при полных счётчиках сеанса,
  выборка окна графика занимает 0,02 мс;
* полоса тревоги не переписывается, пока сообщение не изменилось, — иначе
  скринридер повторял бы одну и ту же аварию каждые 250 мс.

## 12. Ограничения

Честно о том, чего приложение не делает:

* **Ориентация оценивается мгновенно**, триадизацией по акселерометру и
  магнитометру, без гироскопической интеграции. Это демонстрационный расчёт: на
  орбите он шумный, для настоящего решения нужна фильтрация Калмана и
  интеграция по гироскопу с коррекцией по магнитометру.
* **Часть пакетов теряется при большой частоте кадров** — ограничение эмулятора,
  а не пульта; полнота потока измеряется и показывается честно.
* **Глубина истории ограничена** 20 000 пакетами: журнал и выгрузка содержат
  последние 20 000 пакетов, а не весь сеанс. Счётчики и отчёт при этом
  накопительные. Для длинного сеанса выгружайте журнал частями.
* **Тесты интерфейса не заменяют проверку на реальном конструкторе.** Набор
  `tests/run_all.py` проверяет синтаксис, связи разметки/кода/стилей, требования
  ТЗ и сборку автономного HTML. Проверка на физическом спутнике остаётся отдельным этапом.
* **Команды в файловом режиме не доходят до борта**: у эмулятора нет приёмника
  команд (раздел 7).
* **Данные никуда не отправляются** — журнал и настройки лежат в `localStorage`
  браузера, очищаются кнопкой в настройках.

## Инструменты анализа
Выбор параметра и временного окна, статистика min/max/среднее/стандартное отклонение, поиск подозрительных выбросов по MAD, сводная таблица по датчикам и экспорт CSV. Выбросы являются эвристическими маркерами, требующими проверки оператором.
